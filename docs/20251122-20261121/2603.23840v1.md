## 摘要
随着对智能车载体验需求的增长，车载智能体正从简单助手演变为长期伴侣。这一演进要求智能体持续建模多用户偏好，并在用户间偏好冲突和习惯随时间变化的情况下做出可靠决策。然而，现有基准大多局限于单用户、静态问答设置，未能捕捉偏好的时间演化以及真实车辆环境中多用户、工具交互的特性。为填补这一空白，我们提出VehicleMemBench，一个基于可执行车载仿真环境构建的多用户长上下文记忆基准。该基准通过将动作后的环境状态与预定义目标状态进行比较来评估工具使用和记忆，从而实现无需基于大语言模型或人工评分的客观且可复现的评估。VehicleMemBench包含23个工具模块，每个样本包含超过80条历史记忆事件。实验表明，强大模型在直接指令任务上表现良好，但在涉及记忆演化的场景中表现不佳，尤其是当用户偏好动态变化时。即使是先进的记忆系统也难以处理该环境中的领域特定记忆需求。这些发现凸显了需要更稳健和专门的记忆管理机制，以支持真实车载系统中的长期自适应决策。为促进未来研究，我们发布了数据和代码。

## Abstract
With the growing demand for intelligent in-vehicle experiences, vehicle-based agents are evolving from simple assistants to long-term companions. This evolution requires agents to continuously model multi-user preferences and make reliable decisions in the face of inter-user preference conflicts and changing habits over time. However, existing benchmarks are largely limited to single-user, static question-answer settings, failing to capture the temporal evolution of preferences and the multi-user, tool-interactive nature of real vehicle environments. To address this gap, we introduce VehicleMemBench, a multi-user long-context memory benchmark built on an executable in-vehicle simulation environment. The benchmark evaluates tool use and memory by comparing the post-action environment state with a predefined target state, enabling objective and reproducible evaluation without LLM-based or human scoring. VehicleMemBench includes 23 tool modules, and each sample contains over 80 historical memory events. Experiments show that powerful models perform well on direct instruction tasks but struggle in scenarios involving memory evolution, particularly when user preferences change dynamically. Even advanced memory systems struggle to handle domain-specific memory requirements in this environment. These findings highlight the need for more robust and specialized memory management mechanisms to support long-term adaptive decision-making in real-world in-vehicle systems. To facilitate future research, we release the data and code.

  - 记忆类基准（如 LongBench、PerLTQA、LongMemEval）多为**单用户、静态问答**，无法刻画偏好的时间演化与多用户交互。
  - 工具使用类基准（如 τ-bench、StableToolBench、VehicleWorld）侧重**短程指令遵循**，缺乏长期、演化中的用户偏好建模。
  - 二者交叉处（多用户 + 长期记忆 + 可执行工具交互 + 状态级评测）尚无基准覆盖。
- **整体含义**：论文提出 **VehicleMemBench**，一个基于可执行车载仿真环境的多用户长上下文记忆基准，用"动作后环境状态 vs 预设目标状态"的比对替代 LLM/人工打分，实现客观、可复现的评测，从而回答"记忆是否是车载智能体的主要瓶颈"这一核心问题。

## 2. 方法论

### 2.1 核心思想
将"多用户偏好演化"建模为**结构化事件链**，在统一时间轴上交错排列，转化为自然对话历史；再把可执行的车载偏好链末端接上"延迟查询 + 已验证参考工具序列"，使记忆能力可以通过**环境终态是否匹配**来客观判定。

### 2.2 数据构建五阶段流水线
- **Stage 1 人格组生成**：从 Persona-Hub 精英子集采样 100 组、每组 3 名用户，用 LLM 丰富为结构化画像（基本信息、文化兴趣、生活习惯、车载偏好），人工筛选保留 50 组。
- **Stage 2 事件链构建**：每条链 $C_i=(e^i_1,\dots,e^i_{n_i})$ 是围绕相关偏好的逻辑连贯事件序列；设计 5 类偏好动态：**偏好冲突、条件约束、共指消解、状态迁移、错误纠正**；同时混入非车载偏好链作为干扰项。
- **Stage 3 时间交错**：为每个事件赋予时间戳 $t^i_j$，合并所有链并按时间排序得到全局序列 $S=(e_1,\dots,e_N)$，模拟多线程偏好并发演化。
- **Stage 4 对话生成**：以 $(e_t, p^{u}_{t-1}) \rightarrow p^{u}_t$ 的方式，条件于当前事件、历史摘要与上一步偏好状态生成多轮对话，偏好以"闲聊式旁白"而非显式指令出现（提高难度）。
- **Stage 5 问答生成**：仅针对车载可执行链生成查询，LLM 生成参考工具调用序列，人工审核并在仿真器中执行验证目标状态。

### 2.3 可执行仿真环境
- 基于 VehicleWorld 重构，覆盖 **23 个车载设备模块**、封装 **111 个可执行 API**（如 `carcontrol_seat_set_heating_level`）。
- 每个设备有结构化状态表示、可执行动作与参数约束；提供统一记忆 API 以接入各类记忆系统。
- 工具发现机制：初始仅暴露 `list_module_tools(module_name)` 元工具，按需动态加载模块 API，避免工具集过载。

### 2.4 评测协议与指标
- **离线记忆摄入 + 在线交互执行**：先 $M \leftarrow \text{ADD}(M,D)$ 构建记忆；评测时智能体按策略 $a_t=\pi(q,m_t,v_t,h_t)$ 交替执行记忆检索 $m_t\leftarrow\text{RETRIEVAL}(M,q_t,k)$ 与环境动作 $v_{t+1}=f(v_t,a_t)$，直至终止得到 $v_{pred}$。
- **状态转移定义**：$\Delta_{ref}=\{f_i \mid v^{ref}_i \neq v^{init}_i\}$，$\Delta_{pred}$ 同理。
- **指标**：
  - **ESM（Exact State Match）**：$\mathbb{1}[v_{pred}=v_{ref}]$，严格成功判据（少量文本参数用模糊匹配）。
  - **字段级/值级 F1**：$TP_{field}=|\Delta_{pred}\cap\Delta_{ref}|$，$TP_{value}$ 进一步要求值相等，计算 P/R/F1。
  - **效率指标**：平均工具调用次数 Calls、每次检索的平均记忆 token 数 MemToken。
  - **记忆能力分**：$\text{MemoryScore}=\text{ESM}_{auto}/\text{ESM}_{gold}$。
- **三个评测维度**：整体任务表现、工具使用能力（给 Gold Memory 隔离记忆因素）、记忆能力（自主记忆 vs Gold Memory 对比）。

## 3. 实验设计

- **数据集/场景**：自建 VehicleMemBench，50 个人格组、150 个用户画像、500 条可执行查询、1500 条交错事件链；每实例平均 81.78 个事件、约 92,819 token 历史（GPT-4o 分词器），查询本身平均仅 37.63 token；查询按推理类型分布为偏好冲突 149、条件约束 102、共指消解 97、状态迁移 90、错误纠正 62；目标模块以导航（96）、座椅（85）、灯光（64）、空调（64）为主。
- **对比模型（7 家族 12 个模型）**：Gemini-3-Pro-Preview、GPT-5、Doubao-Seed-1.6、MiniMax-M2.1/M2.5、GLM-4.7/4.7-Flash/5、Kimi-K2/K2.5、Qwen3-Max/Qwen3.5-397B-A17B。
- **对比记忆系统（7 种）**：场景定制基线 Recursive Summarization、Key Value Store；通用系统 MemOS、Mem0、LightMem、Memobase、Supermemory；均以 Gemini-3-Pro-Preview 与 Qwen3-Max 为骨干模型。
- **记忆设置**：Gold Memory、Recursive Summarization、Key Value Store、无记忆（附录 D）四种条件。
- **失败模式分析**：人工检查输出，划分为记忆错误、多余调用、执行错误、执行不完整四类，并按推理类型细分。

## 4. 资源与算力

- 论文**未使用本地 GPU 训练或推理**，所有模型均通过 OpenAI 兼容 API 调用，因此未报告 GPU 型号、数量或训练时长。
- 仅给出 API 调用量级估计：无记忆设置下全数据集单模型约需 **1000–1500 次 API 调用**；引入记忆系统（如递归摘要、MemOS）后总调用常**超过 5000 次**，主要开销来自记忆构建与更新，且记忆构建有强顺序依赖，中断会影响结果。
- 数据生成阶段使用 Gemini-3-Pro-Preview（画像丰富、事件链、答案生成，温度 0.7/0.8/0.0）与 GPT-4.1（对话生成，温度 0.7）。

## 5. 实验数量与充分性

- **实验组规模**：约 12 个模型 × 4 种记忆设置（Gold / Rec.Sum. / KV / 无记忆）+ 7 个记忆系统 × 2 个骨干模型 × 5 类推理类型的分类别结果 + 失败模式人工分析 + 效率（MemToken）分析，整体实验矩阵较完整。
- **充分性**：
  - 覆盖主流闭源/开源模型家族与代表性记忆系统，横向对比面广。
  - 通过 Gold Memory 与自主记忆的对照，成功将"工具使用能力"与"记忆能力"解耦，归因清晰。
  - 无记忆设置（ESM 普遍 <20）有效验证了基准确实强制依赖长期记忆，排除了参数化知识捷径。
- **客观性与公平性**：
  - 状态级精确匹配避免了 LLM/人工评分的偏差，可复现性强。
  - 所有模型统一超参（温度 0、最大 8192 token、最多 10 轮工具调用、失败重试 3 次）。
  - 数据经三人独立标注、Cohen's κ 检验（0.69–0.77）并人工修正至 100% 正确。
- **潜在不足**：受算力成本限制，每个配置仅报告单次结果，未报告方差/置信区间；未做系统的消融实验（如事件链类型数量、历史长度、干扰链比例的敏感性分析）。

## 6. 主要结论与发现

- **记忆是主要瓶颈**：Gold Memory 下强模型 ESM 很高（Gemini-3-Pro-Preview 达 90.60，字段/值 F1 为 96.13/94.81），但切换到自主记忆后大幅下降（Gemini 降至 64.80，Doubao 从 85.40 降至 59.00）；所有模型因记忆不足造成的性能损失均超过其工具使用能力的剩余差距。
- **工具能力本身仍有分化**：即使给 Gold Memory，最强与最弱模型（Gemini vs GLM-4.7-Flash）差距超 35 分，说明高质量记忆不足以弥补工具调用能力短板。
- **自主记忆只保留粗粒度偏好**：Gold 设置下字段级与值级 F1 差距仅 1–2 分，自主记忆下扩大到近 10 分，说明能定位设备/字段但难以恢复精确取值。
- **同家族版本迭代收益有限**：MiniMax M2.1→M2.5、GLM-4.7→GLM-5 提升幅度小，未根本改善长期多用户记忆表现。
- **通用记忆系统不如简单领域基线**：Memobase 等表现甚至低于 Recursive Summarization 与 KV Store；通用系统常保留无关偏好引入噪声。
- **难度分布不均**：**条件约束最难**（如 Qwen3-Max 在 Rec.Sum. 下 51.96 vs 偏好冲突 67.79），偏好冲突相对容易，说明主要挑战不是多用户干扰，而是上下文敏感偏好的建模；状态迁移与错误纠正在扁平 KV 表示下困难，在带时序上下文的表示（如 Supermemory）下改善明显。
- **准确率与效率难以兼得**：Supermemory 准确但检索成本高（约 960 token/次），KV Store 高效但准确率低。
- **失败模式**：记忆错误占全部错误的 **63.9%**，远超多余调用、执行错误与执行不完整。

## 7. 优点

- **评测范式创新**：以环境终态精确匹配替代 LLM/人工打分，客观、可复现、可细粒度归因（字段级/值级 F1、错误类型分布）。
- **数据构造可扩展**：事件链 + 时间交错的结构化流水线，能系统性地注入 5 类偏好动态，并天然支持多用户与长上下文。
- **干扰项设计贴近真实**：非车载偏好链作为干扰、偏好以"闲聊旁白"而非显式指令出现，显著提升检索与过滤难度，避免"指令日志式"捷径。
- **能力解耦清晰**：Gold Memory vs 自主记忆的对照 + MemoryScore 指标，把工具能力与记忆能力分离评估。
- **质量控制严谨**：三标注者共识 + Cohen's κ + 全量人工修正（事件对齐 16.6% 错误、查询 8.4%、答案 12.4% 均被修正）。
- **工程完备**：111 个 API、按需工具发现机制、统一记忆接口，便于接入各类记忆系统并复现。

## 8. 不足与局限

- **模型覆盖有限**：作者自述受资源限制仅评测代表性模型，未覆盖全部方法；每个配置单次运行，缺乏方差与显著性检验。
- **场景复杂度有限**：聚焦核心任务设置，未扩展到更长时程交互、多模态输入（语音/视觉）或真实车机时延等复杂场景。
- **数据合成偏差风险**：历史对话与查询均由 LLM 生成（Gemini/GPT-4.1），尽管经人工修正，仍可能残留风格化痕迹或系统性偏差；人格源自 Persona-Hub 合成数据，真实用户分布代表性存疑。
- **评测依赖仿真器保真度**：状态匹配基于 VehicleWorld 重构的仿真环境，与真实车机系统的行为差异可能影响结论外推。
- **成本门槛高**：记忆构建阶段 API 调用常超 5000 次且顺序依赖强，限制了大规模、多轮重复评测的可行性。
- **指标局限**：ESM 为严格全匹配，对"部分正确"的惩罚较重；MemoryScore 为比值指标，在 Gold ESM 较低时解释力下降。
- **应用限制**：作者指出记忆建模或决策错误在安全关键的车载场景中可能影响用户体验与系统可靠性，部署前需更稳健的评估。
