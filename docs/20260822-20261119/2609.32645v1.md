## 摘要
自动驾驶问答需要对结构化场景信息进行推理，然而现有的视觉-语言方法在很大程度上将异构推理操作交由单一的神经推理过程完成。我们认为，这种统一策略忽视了一个根本性区别：有些查询存在精确的符号解，而另一些则需要语义解释。我们提出一种查询自适应的神经符号推理框架，根据查询的性质显式分配计算资源。其核心是一个分层时空场景图（STSG），它将持续存在的对象身份与帧特定状态分离，并将空间关系和时间转换表示为显式的有向结构。给定一个查询，符号执行器首先尝试通过精确的图操作来求解；只有当符号执行弃权时，才调用大语言模型进行语义推理。对于这些未解决的查询，查询条件化的图检索与证据过滤保留了关系方向、时间局部性和对象语义，为大语言模型提供紧凑且经过验证的任务相关证据。这一设计将大语言模型从通用推理引擎转变为有针对性的语义推理器，同时使确定性计算得以精确且高效地处理。我们在 oracle 感知设置下，对 nuScenes v1.0-mini 全部十个场景中的 5,916 个 NuScenes-QA 问题进行了评估。完整系统在使用 GPT-5.4-mini 时达到 80.63% 的总体准确率，相比对应的纯大语言模型配置提升了 5.48 个百分点；使用 DeepSeek-V4-Flash 时，提升达到 6.64 个百分点。最大的增益出现在计数问题上，分别提升了 10.20 和 12.61 个百分点。这些结果表明，选择性推理同时提升了准确率和推理效率。

## Abstract
Autonomous-driving question answering requires reasoning over structured scene information, yet existing vision-language approaches largely delegate heterogeneous reasoning operations to a single neural inference process. We argue that this uniform strategy overlooks a fundamental distinction: some queries admit exact symbolic solutions, while others require semantic interpretation. We introduce a query-adaptive neuro-symbolic reasoning framework that explicitly allocates computation according to the nature of the query. At its core is a hierarchical Spatiotemporal Scene Graph (STSG) that separates persistent object identities from frame-specific states and represents spatial relations and temporal transitions as explicit directed structures. Given a query, a symbolic executor first attempts to resolve it through exact graph operations; only when symbolic execution abstains is an LLM invoked for semantic reasoning. For these unresolved queries, query-conditioned graph retrieval and evidence filtering preserve relation direction, temporal locality, and object semantics, providing the LLM with compact and verified task-relevant evidence. This design shifts the role of the LLM from a universal reasoning engine to a targeted semantic reasoner, while allowing deterministic computation to be handled exactly and efficiently. We evaluate the framework on 5,916 NuScenes-QA questions across all ten scenes of nuScenes v1.0-mini under an oracle-perception setting. The complete system achieves 80.63 percent overall accuracy with GPT-5.4-mini, improving over the corresponding LLM-only configuration by 5.48 percentage points; with DeepSeek-V4-Flash, the improvement reaches 6.64 points. The largest gains occur on counting questions, with improvements of 10.20 and 12.61 points, respectively. These results show that selective reasoning improves both accuracy and inference efficiency.

## 1. 核心问题与研究动机

- **背景**：自动驾驶正从“感知”走向“结构化推理”，需要回答存在性、计数、空间关系、状态、比较等关系型问题（如“某区域内是否有某物体”“满足空间约束的物体有几个”）。
- **核心问题**：现有视觉-语言方法（如 DriveGPT4、DriveVLM、DriveLM）普遍把**异构推理操作统一交给单一神经推理过程**，隐含假设“所有查询都应通过神经语言推理求解”。
- **作者的核心论点**：存在一个根本性不对称——
  - 部分查询具有**确定性语义**（存在性可直接验证、空间约束可用图操作求值、计数在候选集确定后可精确执行），强制 LLM 用自由生成复现这些操作会引入不必要的不确定性与算力开销；
  - 另一部分查询涉及**语义歧义或组合式解释**，难以被固定符号规则覆盖。
- **因此**：关键问题不是“符号 vs 神经”二选一，而是**决定何时用哪一种**——即把推理建模为**查询自适应的计算分配问题**。

## 2. 方法论

### 2.1 核心思想
- 构建分层**时空场景图（STSG）**作为结构化记忆；查询先由**保守符号执行器**尝试精确求解，**仅在符号执行弃权（abstention）时**才调用 LLM；对未解决查询，先做**查询条件化图检索 + 证据过滤**，再交给 LLM 做语义推理。
- LLM 的角色从“通用推理引擎”转变为“定向语义推理器”。

### 2.2 关键技术细节

**(1) 分层时空场景图表示** G = (V, E)
- 节点集：持久实体节点 V_ent（跨帧稳定身份）、帧级状态节点 V_state（记录 `(i, t, a_{i,t})`，含类别、运动状态等属性）、自车参考节点 v_ego。
- 边集：
  - **空间关系边** E_spat：基于 BEV 中心位移 `Δp_{i|j,t}` 与方位角 `θ_{i|j,t} = atan2(Δy, Δx)`，按 NuScenes-QA 的六方向谓词映射 φ(θ) 生成**有向**边（主体→参考），参考可为自车。
  - **层级边** E_hier：`(v_ent_i, HAS STATE, v_state_{i,t})`。
  - **时间转移边** E_temp：相邻观测间 `(v_state_{i,t(k)}, NEXT STATE, v_state_{i,t(k+1)})`，形成显式状态轨迹。
- 设计要点：分离“持久身份”与“帧级状态”，避免同一物体多次观测被当作独立实体；有向边显式化关系方向，降低推理中方向反转风险。

**(2) 结构化图投影与索引**
- 完整图 G 作为符号记忆保留；另派生检索视图 `G_R = Π_R(G)`，保留实体标识、关系方向、时间引用，直接以结构化 custom-KG 方式插入 **LightRAG** 图-向量索引，跳过“图→文档→LLM 再抽取”的中间环节，保持原子三元组语义。

**(3) 神经符号双引擎问答**
- **符号优先路由**：`a_sym = Φ_sym(Q, G, t_q) ∈ Y ∪ {⊥}`。支持存在性、计数（统计**持久全局标识**而非帧级状态）、以及候选唯一时的类别/状态查询；不支持或多解时返回 ⊥（比较类问题在 Full 配置中一律弃权）。
- **神经回退检索**：`H⁰_Q = R(Q ⊕ h(t_q); G_R)`，随后确定性过滤 `H_Q = F_filter(H⁰_Q; t_q, C_q, R_q, Q)`，施加四类约束：帧约束、语义（类别）约束、方向约束、自车指代约束。
- **最终路由**：`â = a_sym`（若 ≠⊥），否则 `Φ_llm(Q, H_Q)`；证据序列化为问题类型专用 prompt，输出 JSON `{"answer": "value"}`，答案空间按题型限定并做规范化（别名、大小写、下划线等）。

## 6. 主要结论与发现

- **准确率**：Full + GPT-5.4-mini 达 **80.63%**（4,770/5,916），较 LLM-only（75.15%）**+5.48 pp**；Full + DeepSeek 达 **77.89%**，较 LLM-only（71.25%）**+6.64 pp**。
- **计数题收益最大**：GPT 65.45%→75.65%（+10.20 pp），DeepSeek 62.56%→75.17%（+12.61 pp），说明精确候选集操作与身份过滤对枚举类问题互补性强。
- **题型分布**：Full GPT 在存在性（88.80%）、计数、物体（69.88%）、状态（93.26%）上最佳；比较题最佳为 GPT LLM-only（76.21%），Full GPT 为 74.08%。
- **效率**：Full 相对 LLM-only 降低 QA 运行时间 **30.3%（GPT）** 与 **43.5%（DeepSeek）**，且**每个场景均观察到下降**；摊销到每题约 15.11 s vs 21.68 s（GPT）、22.99 s vs 40.69 s（DeepSeek）。
- **Symbolic-only 基线**：61.43% 总体（存在性 76.22%、比较 65.57%），显著低于两种神经配置，尤其在计数与物体题上——反映固定规则在语言变体、歧义指代、多候选情形下覆盖有限，从而支撑“符号+神经回退”的组合动机。
- **总体论断**：神经符号在结构化驾驶场景中的收益**并非来自处处耦合两个模块**，而来自**按查询性质选择性分配计算**。

## 7. 优点

- **问题表述清晰且有洞察力**：把“符号 vs 神经”重构为“何时用哪个”的计算分配问题，并以**弃权机制**作为路由闸门，使符号模块不只是 LLM 的辅助工具，而是决定是否需要神经推理的门控。
- **表示设计合理**：实体/状态两层分离 + 有向空间边 + 显式时间转移边，兼顾跨帧身份一致性与帧级精确操作；有向边显式化直接针对“关系方向易反转”这一实际错误源。
- **检索设计有针对性**：绕过“图→文档→LLM 重抽取”流程，直接以结构化 custom-KG 插入 LightRAG，保留原子三元组语义；四类确定性过滤（帧/语义/方向/自车指代）针对稠密检索易混淆极性、方向、限定语的已知问题。
- **无需微调**：任务适配完全通过图模式、符号规则、过滤规则与题型 prompt 实现，工程可迁移性好，后端可替换。
- **可解释性**：显式实体 ID、帧关联、有向关系与符号候选集、过滤后证据均可检查，便于错误分析。
- **实验报告诚实**：明确区分 Symbolic-only 与严格消融、主动指出比较题差异不可归因于符号执行、明确计时边界（排除构图与索引）与 API 延迟影响。

## 8. 不足与局限

- **感知设置理想化**：oracle-perception 使用真值标注，未评估学习式感知误差的传播；作者亦承认模块化接口不能阻止感知错误影响下游答案。
- **时间结构未被验证**：虽构建 NEXT STATE 边，但评估问题均为帧特定问题，**跨帧推理收益未获实证**，这是表示设计中最大的“未兑现承诺”。
- **数据规模有限**：仅 nuScenes v1.0-mini 的 10 个场景、404 帧、5,916 题，场景短（39–41 帧）、无 padding/截断；对完整 nuScenes 及更长序列的可扩展性未知。
- **符号路径的脆弱性**：符号答案依赖查询解析器覆盖度与图事实正确性；解析失败或多解即弃权，弃权率与路由覆盖率未系统报告。
- **神经路径的脆弱性**：确定性过滤只能剔除不兼容记录，**无法召回未被检索到的相关事实**；过滤过严可能丢弃有用证据（作者自述）。
- **比较题上的异常**：Full GPT 在比较题上低于 LLM-only GPT（74.08% vs 76.21%），虽被解释为随机性/检索生成差异，但缺乏多种子重复实验来量化方差，结论稳健性存疑。
- **效率度量非严格**：墙钟时间含远程 API 延迟、排队与重试，绝对数值不可跨环境复现；未报告 token 消耗或 API 调用次数等更中性的成本指标。
- **缺少关键消融**：未单独消融证据过滤模块、有向边、层级结构、时间边各自的贡献；未分析符号路由覆盖率与准确率的关系。
- **应用限制**：依赖高质量结构化 3D 观测接口；符号规则需针对问题模板定制，迁移到开放域或新题型需额外工程；比较/多跳类问题仍完全依赖 LLM。
