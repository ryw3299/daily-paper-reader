## 摘要
一个回答知识图谱问题的 LLM 智能体会为每个问题编写程序，其工具则从头评估每个程序。我们为智能体提供一个 Datalog REPL，即动态 Datalog 引擎上的会话；在其中，规则像事实一样被插入和撤回，而派生事实保持最新。提示缓存复用模型对会话共享内容的处理，而 Datalog REPL 复用对共享内容的求值。在三个知识图谱上的问题链中，使用两个模型时，智能体在 180 个案例中的 179 个里复用了 REPL 保留的关系，并写出更少的输出 token：SQL 和 Python 智能体多写 23% 至 82%。使用 SQL 表或 Python 命名空间时，Claude Haiku 5.5 几乎不为后续问题存储任何内容；在 1300 万条事实下，七个问题组成的链对其而言中位耗时为 48 秒和 56 秒，而使用 REPL 时为 31 秒。Claude Opus 5.5 通过在 SQL 中存储表来匹配 REPL；当数据变化时，它存储视图，而视图在每次读取时都会重新求值。REPL 保留的关系既能像表一样被读取，又能像视图一样保持最新。Datalog 是 SQL 和 Python 之外的小众语言；在启用思考功能时，模型使用它回答的准确性与使用其他语言相当。

## Abstract
An LLM agent that answers questions about a knowledge graph writes a program per question, and its tools evaluate each from scratch. We give the agent a Datalog REPL, a session over a dynamic Datalog engine, in which rules are inserted and retracted like facts while derived facts stay current. Prompt caching reuses the model's processing of what a session shares, and the Datalog REPL reuses the evaluation of it. On chains of questions over three knowledge graphs, agents reuse a relation that the REPL keeps in 179 of 180 cases, with two models, and write fewer output tokens: SQL and Python agents write 23 to 82% more. With SQL tables or a Python namespace, Claude Haiku 5.5 stores almost nothing for later questions, and a chain of seven questions at 13 million facts takes it a median of 48 and 56 s, against 31 s with the REPL. Claude Opus 5.5 matches the REPL by storing tables in SQL, and when the data changes it stores views, which are evaluated again at every read. A relation that the REPL keeps is read like a table and stays current like a view. Datalog is a niche language beside SQL and Python, and with thinking enabled the models answer as accurately with it.
