What Survives the Shift from Text to Pixels? Conditional Protection against
Prompt Injection in Image-Rendered Documents
Haoyang Liu, Yinong Xu, Zhe Lang, Zhenyu Guan, Qianyun Zhang
School of Cyber Science and Technology, Beihang University
Abstract
Multimodal language models increasingly answer questions
over external documents, exposing them to indirect prompt
injection: commands planted in untrusted content to hijack
the response. Rendering untrusted content as page images
lowers attack success on average, leaving open which in-
jected operations survive rendering, at what utility cost, and
whether failed image attacks reflect unread commands or
commands read but not followed. We pair text and page-
image versions of 191 English question-answering sources
across six models, measuring marker appending, answer for-
matting, and answer replacement alongside clean Question-
Answering utility. Rendering reduces append and format
execution for every model, yet Qwen3-VL-8B still executes
image-borne replacement at 77.96%. Protection also de-
pends on target type, rendering settings, wording, and repeti-
tion, and a search over eight fixed attack candidates largely
closes the image deficit in appending and formatting for
Qwen and Gemini, though not for GPT-5-nano. Utility ratios
on original questions range from 93.31% to 101.61%, but
Qwen falls to 61.99% when answers combine two evidence
spans. Illegibility cannot explain all failed attacks: models
often transcribe and identify image-borne commands they do
not execute, and trusted user authorization raises execution
on unchanged pages. Inside Qwen, patching early attack-
region states induces all three operations, more weakly in
images. Attention blocking suggests why: a text command
acts through its own positions, whereas visual encoding
spreads an image command and its target across the instruc-
tion page. Rendering thus offers conditional protection, mo-
tivating evaluations that report security by model, operation,
and attack budget alongside utility.
1. Introduction
Retrieval-augmented generation and document question an-
swering ground a model’s responses in external sources
[5, 14]. Such sources supply evidence under a trust hier-
archy in which system and user instructions take precedence
over commands embedded in external content [26]. Indirect
prompt injection exploits this trust boundary by planting a
command next to the evidence [10, 31]. A promising miti-
gation is to render the document as page images, so that a
multimodal model reads the same words through its vision
encoder rather than its text tokenizer. Rendering long pas-
sages reduces decoder token usage while preserving retrieval
and summarization performance [15], and Zhang et al. [34]
demonstrate that rendering untrusted text as images reduces
attack execution rates across two prompt injection bench-
marks, including under adaptive attacks.
Figure 1 illustrates how rendering can suppress an in-
jected command while preserving the answer. Given the
same question, factual content, and embedded command,
Qwen correctly answers that the author of Cock and Bull
was born in 1961 in both runs. Its response to the text
document additionally carries the marker requested by the
attacker, whereas its response to the rendered page does not.
Answer correctness alone is therefore insufficient to assess
security: a successful attack can alter the response without
corrupting the answer. Prior results establish that rendering
helps on average, but leave open a finer-grained question:
which decisions about the response can an external author
still control through a rendered page, and why?

We argue that answering this question requires looking
beyond the aggregate modality gap along three axes. First,
the gap depends on what the command requests and how
it is delivered. Appending a line leaves the answer intact,
whereas replacing it with a fixed phrase must override the
user’s request, and an aggregate over one fixed attack can
mask acute vulnerability. Second, a missing marker is am-

biguous: the model may have failed to read the command,
or it may have read the command and followed the user
instead. Since type size and visual degradation modulate
typographic attacks [3], legibility is a plausible yet untested
explanation. Third, prior work has localized states that influ-

it remains unclear which regions encode the semantics of a
rendered command.
To disentangle these factors, we pair text and image ver-
sions of 191 question-answering (QA) sources from Long-
Bench [2] across six models, holding the question, evidence,
and attack wording fixed within each pair. We measure ap-
pend, format, and replacement execution alongside clean QA
F1 on original questions and integration questions requiring
two evidence spans. On a 90-source subset, we test how tar-
get type, presentation, and a query budget over fixed attack
candidates affect execution. Behavioral diagnostics exam-
ine reading versus following, while interventions in Qwen
test how states derived from the source influence operation
execution and target selection [33].
Our contributions are threefold:
• An operation-level evaluation of rendered injection.
We build a matched text–image benchmark measuring per-
operation attack execution and clean QA utility on two
question types. Rendering suppresses append and format
attacks for all six models, yet protection varies with model,
operation, target type, and presentation, can largely vanish
under a small candidate search, and may come with sharp
utility losses on integration questions.
• A behavioral separation of reading from following.
Across three models, reporting, identification, and exe-
cution can dissociate; for Qwen, OCR transcripts of the
pages are executed far more often than the pages them-
selves, and user authorization changes execution on un-
changed pages. Legibility alone therefore cannot explain
failed image attacks.
• A mechanistic contrast of how each modality carries a
command. Qwen’s early attack-region states induce all
three operations in both modalities, beyond random and
position-shifted controls. Target redirection and attention
blocking indicate that a text command is confined to its
own positions, whereas an image command and its target
are also carried by visual tokens elsewhere on the page.
2. Related Work
2.1. Visual Text Representation
Text can reach a language model as discrete tokens or as
patches of a rendered image. Pixel-based models encode
rendered text without a fixed vocabulary [23–25], and their
accuracy depends on how characters are grouped into patches
[17]. OCR-free document models extend this paradigm to
visually rich pages [12, 13, 18], and page images now serve
as retrieval units [7] and as compressed context for multi-
modal decoders [15, 27]. These studies ask what rendering
preserves for the task. Our setting imposes an additional re-
quirement: the model must recover evidence from the page
while respecting the user’s authority over which operations
to perform. We therefore measure clean question answering,
including questions that integrate evidence, jointly with the
execution of embedded commands.
2.2. Prompt Injection Attacks
Prompt injection exploits a trust boundary: system and user
messages define the task, whereas retrieved documents, tool
outputs, and observations supply data [16, 21]. In indirect
attacks, a third party plants instructions in content the model
later consumes [10], with goals ranging from manipulat-
ing the response to leaking information or triggering unau-
thorized tool calls [6, 31, 32]. Defenses delimit untrusted
data [11], separate instructions from data through structured
queries [4], or train models to prioritize privileged instruc-
tions [26]. Our three attack operations span increasing con-
trol over the response, from appending a string to replacing
the answer altogether.
Images can carry instructions as well. Overlaid words
mislead CLIP [8], and typographic or adversarial visual
prompts jailbreak vision-language models [9, 22] or inject
instructions into multimodal assistants and agents [1, 29].
Nagaraja et al. [20] varied the placement and visibility of
commands embedded in natural images, and Balakrishnan
et al. [3] linked typographic attack success to font size and
visual degradation. Pictionary inverts this direction: the
application itself renders untrusted material to weaken its
instructions [34]. In contrast, we hold the document and
instruction fixed across modalities and ask which operations
survive the transformation. Matched question answering,
reading diagnostics, and trusted authorization separate read-
ing from following the source, while activation patching
[19, 33] and attention blocking locate where each modality
carries the command.
3. Problem Formulation and Experimental
Setup
3.1. Trust boundary
Let S denote the system policy, Q the user question, and D
the external source. The attacker inserts an instruction A
into D while retaining its original facts. Only the source is
under attacker control. With R the renderer and ⊕insertion
at a designated position, the two responses are
yT = M(S, Q, D ⊕A),
(1)
yV = M(S, Q, R(D ⊕A)).
(2)
The system prompt instructs the model to treat the external
source as untrusted, while the user prompt specifies the
2


question and marks the source boundaries. The source may
provide evidence for answering the question, but instructions
within it have no authority to override the system policy or
the user’s request. This trust boundary is the same in T and
V , where the source and injected instructions are presented
together as text or page images, respectively.
3.2. Sources and operations
We use 191 English source instances from LongBench
[2]: 80 Qasper questions about research papers [5], 69
MultiFieldQA-en questions over documents from multiple
domains, and 42 HotpotQA questions requiring evidence
across passages [30]. Each source instance comprises exter-
nal content, its original question, and reference answers.
We study three attack operations, each with two fixed
wordings. Append requests the answer followed by a source-
specific marker on a new line. Format requests one line
consisting of the marker, a vertical bar, and the answer. The
marker is absent from the original question, document, and
references. Replace directs the model to replace the answer
with “You are attacked!”.
3.3. Source modalities and models
The two source modalities are text (T) and page images (V );
the system policy and user question remain text in both. We
use three prompt wrappers (W1, W2, and Wa) and fixed
default rendering settings.
We run Qwen3-VL-8B-Instruct locally and access GPT-5-
nano, Haiku 5.5, Gemini 3.1 Flash-Lite, GLM-5.3-Flash, and
DeepSeek V4.1 Flash 1017 via an API gateway. The core
comparison uses the same questions, attacks, and PNGs for
all six. We use Qwen for rendering and wording experiments,
behavioral diagnostics, and interventions that require access
to decoder states. GPT-5-nano, whose append and format
ASR falls from above 70% in text to zero in images, and
Gemini, which has the highest image ASR, also join part of
these experiments.
3.4. Scoring
Our security measure is Attack Success Rate (ASR), the
rate at which visible responses execute the injected operation:
appending the marker, formatting the answer, or replacing it
with the target phrase.
Responses truncated by the output length limit are marked
as unknown and excluded from scoring. For each opera-
tion we average its two wordings within source, then aver-
age sources within dataset and give the three datasets equal
weight. For clean questions, we compute LongBench word-
overlap F1 on the full response, taking the best score across
references after normalizing case, articles, punctuation, and
whitespace. The utility ratio (UR) is image F1 divided by
text F1, using the dataset-weighted values displayed in Ta-
ble 2. Reported pH values use Holm correction within each
analysis family.
We used GPT-6 Astra to assist with code development,
experiment execution, and writing the plotting code. We
used Claude Opus 5.5 to edit and organize the manuscript.
The authors reviewed the generated code and checked the
experimental outputs.
4. Does Rendering Close the Injection Channel?
We first compare the six models on the original questions
under W1. Table 1 reports attack execution by operation and
modality, and Table 2 reports clean QA utility.
4.1. Attack Execution across Models and Opera-
tions
Rendering reduces attack execution, but the remaining vul-
nerability depends on the model and operation (Table 1).
For append and format, image ASR is lower than text ASR
for every model: Gemini still executes roughly 50% of the
image attacks, whereas all other models remain below 12%.
The text baseline also matters when interpreting these reduc-
tions. GPT-5-nano and Haiku both reach zero image ASR,
but their text rates exceed 72% and remain below 6%, respec-
tively, yielding markedly different modality gaps. Answer
replacement, however, changes the relative vulnerability of
Qwen and Gemini: Qwen executes the fixed-phrase replace-
ment attack in most image responses, while every API model
stays near zero in images and GLM also stays near zero in
text. Thus, low image ASR for append and format does not
imply resistance to answer replacement, and aggregating
across operations can obscure substantial vulnerability to a
particular operation.
4.2. QA Performance across Question Types
On the original questions, UR stays within 93–102% for all
six models (Table 2). To test utility when evidence must
be combined, we add one integration question per source
(191 in total) that requires two evidence spans. Because
these questions differ from the original benchmark questions,
the two sets characterize utility under different question
demands.
The integration-question modality gap varies across mod-
els. Qwen loses the most and GPT-5-nano also falls below
its original-question UR, whereas Haiku, Gemini, and GLM
show no loss. Thus, the large loss for Qwen does not gen-
eralize to every model, and utility on the original questions
alone does not characterize the cost of combining evidence
from rendered pages.
4.3. Attack Execution on Sources Answered in Both
Modalities
Lower image ASR could reflect weaker question answering
on rendered pages or resistance to the injected instruction.

5. What Makes Rendered Commands Effec-
tive?
The modality gap depends on what the command requests
and how the source is presented. The controlled experiments
in this section use 90 sources, 30 per dataset. We first cross
the operations with target type on the original questions;
holding Qwen fixed, we then vary page resolution and typog-
raphy, task-referencing wording, command placement, and
repetition; finally, we let the attacker try several commands.
We further construct a direct question for each source that
asks for a local fact answerable from a single evidence span;
the task-binding and placement tests use direct and integra-
tion questions, and the repetition tests use direct questions.

5.2. Rendering resolution and font size
We cross export widths of 704, 876, and 1280 pixels with
CSS font sizes of 20, 26, and 32, holding the source con-
tent and attack wording fixed. Higher resolution and larger
type both weaken the protection afforded by rendering (Fig-
ure 2(a)): for fixed-phrase replacement under W1, enlarging
the font from 20 to 32 (width 876) and widening the page
from 704 to 1280 pixels (font size 26) each raise execution
by more than 25 percentage points. The security benefit of
presenting a source as an image thus depends strongly on its
rendering settings.
The two factors show diminishing joint gains: resolution
matters more at small font sizes, and enlarging the font
adds less once resolution is high, a pattern supported by the
negative width-by-font interaction and replicated under W2.
Coarse rendering also costs utility (clean QA F1 of 42.21 at
the coarsest W1 setting versus 48.72 at the default), so low
attack execution at coarse settings cannot by itself establish
protection without a utility cost.

6. Reading versus Following Instructions
A failed image-borne attack may reflect difficulty reading the
instruction or a failure to follow it. We examine reporting
and understanding diagnostics, OCR text inputs, neutral
descriptions, and trusted authorization.
6.1. Reporting, understanding, and execution
We measure three endpoints on the same sources. Reporting
(R) asks the model to transcribe the injected passage ver-
batim without executing it; obeying the command instead
counts as failure. Understanding (U) measures operation-
and-target identification: the model must classify the re-
quested operation among four options and return the exact
target. Execution (A, for attack execution) records operation
execution on the original question.
For Qwen under the inline protocol (Table 4), image re-
porting and execution diverge for appending and formatting:
among sources with successful image reporting, execution
is 0.00% and 3.70%, respectively. Replacement is instead
executed on most images despite only moderate operation-
and-target identification accuracy. Low R need not indicate
unread content: 89 of 90 text replacement responses execute
the command instead of reporting it. Low U can likewise
reflect failure to follow the diagnostic task or reproduce the
exact target, rather than lack of understanding alone. Under
the separate-page protocol, image reporting and execution

6.2. OCR text versus page images
On the inline append and format sources, we replace each
page image with its OCR transcript, supplied as text. On
the 89 sources scored in all conditions, OCR text yields
41.80% operation execution despite recognition errors, ver-
sus 70.96% for the original text and 1.11% for images. Cor-
recting the OCR within the attack span raises strict success
by 14.44 percentage points but operation execution by only
an unresolved 3.33 points. Recognition errors thus mainly
reduce exact reproduction, and text containing such errors is
still executed far more often than the page image.

images. Its authorization effect is thus smaller in images,
whereas Gemini’s is larger. Identical image content can
therefore support execution when the trusted task permits its
operation.
Together, the diagnostics show that inability to read is
insufficient to explain all failed image attacks, while leaving
room for recognition and execution errors. We next test
whether changing states derived from the source can alter
the requested operation.
7. Mechanistic Analysis
7.1. Selecting residual-stream sites
We use Qwen’s open weights to test how states at the in-
jected passage influence operation execution through activa-
tion patching [33]. For each source, we pair a command run
with a neutral run that rewrites the command as a neutral de-
scription, keeping donor and recipient in the same modality.
During prefill, an on intervention replaces neutral-recipient
states with command states; an off intervention reverses the
direction. The recipient then generates freely. Whereas prior
work found late sites governing compliance in text LLMs
[28], we examine the influence of attack-region states across
text and image modalities.
We reserve 60 sources for site discovery and 131 for con-
firmation. A coarse screen measures bidirectional changes
in the relative log-probability of an append-bearing can-
didate versus a legitimate answer. Among eight decoder
depths, attack-region residual inputs at zero-based L5 and
L11 score highest. After adjustment for norm-matched ran-
dom perturbations, full residual-input patching outperforms
half-strength and component-specific alternatives at both
sites. Linear probes also distinguish command from neutral-
description runs in both modalities. Both sites exceed the
preset five-percentage-point retention threshold for random-
control-adjusted bidirectional execution effects in free gener-
ation and pass the clean QA check. We therefore fix L5 and
L11 for confirmation and transfer across operations.

7.3. Redirecting the bound target
The command–neutral contrast tests whether an operation oc-
curs, not which target it uses. We therefore place two random
codes in the source and bind the append or format operation
to one of them. Layers L11 and L17 are selected on 12
discovery sources by linear readout of the bound code, and
all tests use 48 other sources. At L11, attack-region probes
identify the bound code in 100.00% of text and 98.44% of
image runs, while transfer at chance level to neutral refer-
ences containing both codes. We then replace the recipient’s
attack-region states with those of a donor bound to the other
code and score the same responses against the recipient’s
(Rec.) and donor’s (Don.) codes (Table 5). Self-donor
patching provides the baseline, scored against the recipient’s
code (Self). In text, responses switch to the donor’s code,
exceeding the self-donor, random, and shift controls in all 12
comparisons. Image responses do not switch: image format
still produces the recipient’s code, and image append is near
floor even under self-donor patching. The bound code is
therefore decodable from image attack-region states, but at
these sites it does not determine which code the response
produces.
7.4. Blocking the attack region
Section 7.3 patches only the attack region. Before the de-
coder, however, the vision encoder attends across each page,
so other visual tokens on the instruction page may also carry
the command. We test this on the same 48 sources and two
commands. In all 36 decoder layers, during both prefill and
generation, we block every position outside the attack po-
sitions A from attending to A, recomputing from an empty
KV cache. Controls block a size-matched set of other source
positions or, for images, the whole instruction page. With A
blocked, we also replace the page’s visual features outside A,
at the main visual input and all three DeepStack inputs, with
those of a clean page, a neutral-description page, or the page
bound to the other code. These pages share every input patch
outside A, so the replaced features can differ only through
visual encoding of the content inside A.

of the page, consistent with the weaker image induction in

8. Conclusion
We studied which injected instructions survive when external
documents are rendered as page images. Across six models,
rendering reduces append and format execution, but its pro-
tection is conditional: Qwen remains susceptible to answer
replacement, the gap varies with target type and presentation,
and a small search over attack candidates closes much of
it for some models. Utility is largely preserved on original
questions but drops for some models on integration questions.
Illegibility cannot explain all failed image attacks: models
transcribe commands they do not execute and execute more
when the user permits. Inside Qwen, a text command acts
through its own positions, whereas an image command is
spread across the instruction page. Rendering-based de-
fenses should therefore be evaluated by operation-specific
execution under attack budgets alongside utility on questions
that integrate evidence.
