# PIPETTE : Prompt Injection Purple-Teaming for Robust LLM Agents 

Lipeng He ∗, Yihan Wang ∗B, Jiawen Zhang †, N. Asokan ∗‡ ∗University of Waterloo, †Zhejiang University, ‡KTH Royal Institute of Technology lipeng.he@uwaterloo.ca, yihan.wang@uwaterloo.ca, kevinzh@zju.edu.cn, asokan@acm.org 

Abstract — Large language model (LLM) agents routinely interact with untrusted external data, exposing them to indirect prompt injection (IPI) attacks that hijack agents into executing attacker-chosen tasks. To uncover these vulnerabilities at scale, automated red-teaming methods often leverage rein-forcement learning (RL) to generate attacks that achieve high attack success rates (ASR). Model developers use the attacks discovered during internal red-teaming to harden agents through adversarial training before deployment, acollaborative offensive-defensive process known in cybersecurity as purple-teaming . However, we show that achieving high ASR during red-teaming does not guarantee robustness gains from subsequent adversarial training. Specifically, we find that two state-of-the-art RL-based red-teaming methods, RL-Hammer and PISmith, suffer from mode collapse, repeatedly discovering similar attack strategies whose additional successes add no additional robustness improvements to adversarial training. To address this gap, we introduce P IPETTE , a unified prompt injection purple-teaming framework that effectively converts red-teaming discoveries into defender robustness improvements. PIPETTE employs a dictionary learning-based reward that encourages broader coverage of attack strategies during red-teaming. It also integrates an on-policy adversarial training pipeline tailored to IPI defense, enabling agents to resist attacks while completing legitimate user tasks. Extensive evaluations across agentic benchmarks (AgentDojo and ASB) demonstrate that P IPETTE produces defenders that achieve near-zero attack success rates on static attacks and can withstand strong adaptive attacks, while maintaining benign task utility close to that of the undefended baseline. 

## 1. Introduction 

Large language models (LLMs) are increasingly deployed as autonomous agents that execute multi-step tasks, such as managing emails, querying databases, and invoking external APIs [1], [2]. To complete a user task specified by a trusted user instruction, an LLM agent must process untrusted external data retrieved from third-party sources, including web pages, documents, and tool outputs. Because LLMs cannot reliably distinguish between user instructions and external data [3], an attacker can embed a malicious injected instruction inside external data to override the user instruction and redirect the agent toward an attacker-chosen injection

To harden an LLM agent before deployment, model developers pair automated red-teaming , where a red-teamer probes the agent to discover successful prompt injections, with adversarial training on the discovered attacks so the agent learns to resist them (Figure 1) [7], [8]. Among automated red-teaming methods [9], reinforcement learning (RL) has emerged as the state-of-the-art approach for prompt injection [10], [11], [12]. Instead of manually crafting prompts or optimizing individual attack strings one input at a time [13], [14], RL trains a generative red-teaming policy to synthesize attacks at scale across diverse tasks. Leading RL-based red-teaming methods, RL-Hammer [11] and PISmith [12], achieve high attack success rates (ASR), defined as the fraction of test inputs on which the agent executes the injection task, even against models hardened with prior defenses [15]. Despite the effectiveness of these methods as offensive stress tests, we show that achieving high ASR during red-teaming does not guarantee strong robustness after ad-versarial training . For instance, PISmith achieves higher train-time ASR than RL-Hammer on Qwen3-4B ( 68 .75% 

versus 33 .39% ), yet yields a less robust agent after RL-based adversarial training ( 47 .5% versus 27 .5% ASR under the strongest of three unseen attacks, §3). We attribute this gap in part to an objective mismatch. Prior work on jailbreak defenses shows that robustness to unseen attacks depends on the variety of training attacks and not only on arXiv:2611.24362v1 [cs.CR] 18 Nov 2026 their number [16], [17], yet existing RL-based red-teaming methods optimize their policy primarily to maximize attack success. Such an objective can lead to mode collapse , a failure in which the policy converges to a narrow set of outputs that repeatedly exploit the same vulnerability [16], [18]. Specifically, once the red-teaming policy discovers a single effective attack strategy , a way of overriding the user instruction such as claiming that the user task is already complete, it tends to reuse that strategy across rollouts to collect high reward. To mitigate mode collapse, PISmith [12] and RL-Hammer [11] regularize the red-teaming policy with token-level entropy bonuses or embedding distance rewards. However, because these regularizers measure surface-level text differences rather than how the attack overrides the user instruction, the red-teaming policy can engage in reward hacking by rephrasing sentences or inserting unrelated text while relying on the same attack strategy. As a result, training an agent on thousands of rephrased versions of one attack strategy may patch only a single vulnerability and leave the agent exposed to unseen attacks at deployment. Even when red-teaming uncovers distinct attacks, con-verting those discoveries into a practical defense is a second challenge. A useful prompt injection defense requires pre-serving benign utility on clean inputs and utility under attack 

when external data is contaminated [2]. Unlike jailbreak attacks [19], where the user is the attacker and the agent can refuse the harmful request, an agent under IPI must ignore the injected instruction inside external data while still using the surrounding data to complete the benign user instruction. Yet standard RL defenses [20] train the agent with trajectory-level, outcome-based rewards that assign a single scalar score to the entire trajectory based on whether the task succeeded or failed. Because such a score cannot identify which tokens caused the failure [21], agents trained with these rewards can learn to abort execution or refuse the user whenever external data appears suspicious, and thus sacrifice task completion for lower ASR. To address both challenges, we introduce P IPETTE , a unified prompt injection purple-teaming framework that coor-dinates red-teaming and adversarial training toward a single objective of maximizing the hardened agent’s robustness. First, to mitigate mode collapse, P IPETTE guides the red-teaming policy with a dictionary learning-based reward. We decompose generated attacks into a sparse dictionary of reusable components that capture distinct attack strategies, and reward the red-teaming policy when a successful attack cannot be explained by previously discovered components. Second, to preserve benign utility during adversarial train-ing, P IPETTE trains the agent on the collected attacks by combining reasoning-guided RL with token-level on-policy self-distillation (OPSD) [21], [22]. By assigning credit to individual tokens rather than relying solely on trajectory-level outcome rewards, P IPETTE aims to suppress reasoning and action tokens driven by the injected instruction while reinforcing tokens needed for the user task. We evaluate P IPETTE on two standard IPI benchmarks under static and iterative-adaptive attacks, and summarize our contributions as follows:  

> •

We show empirically that maximizing ASR or surface-level text diversity in state-of-the-art RL-based red-teaming methods [11], [12] does not prevent mode collapse at the strategy level, which likely limits the robustness gains of subsequent adversarial training (§3.2 and §4.1).  

> •

We design a dictionary learning-based strategy coverage reward that guides the red-teaming policy to discover new attack strategies rather than surface-level wording variations (§4.2).  

> •

We pair our red-teaming stage with an on-policy adver-sarial training pipeline using token-level self-distillation to preserve benign utility while resisting injected in-structions (§4.3).  

> •

We show on two benchmarks that P IPETTE compares favorably with existing red-teaming and defense base-lines, with ASR under iterative-adaptive attacks on AgentDojo ranging from 0% to 10% across the three models tested and benign utility remaining close to that of the undefended policies on all four models (§5, Appendix B).

2.3. Red-Teaming for Adversarial Training 

To improve robustness against prompt injections without failing tu, a defender Def can harden an initial base policy 

πθ0 into πθ offline prior to deployment through adversarial training [24], which updates the model weights on contami-nated contexts H′ 

> t

carrying injection strings dadv so that πθ

learns to ignore dadv and complete tu. Prior IPI defenses instantiate adversarial training with several objectives on contaminated contexts: StruQ [3] uses supervised fine-tuning (SFT) to maximize the log-likelihood of clean reference actions; SecAlign [25] and Meta-SecAlign [15] use pref-erence optimization to favor user-aligned responses over hijacked responses; SecOPD [21] uses on-policy distillation from a teacher model conditioned on clean observations; and RL-based adversarial training [20] rewards rollouts that complete tu without executing tadv . While StruQ, SecAlign, and Meta-SecAlign construct contaminated contexts using templated or hand-designed injection strings, hardening πθ0

against stronger attacks requires exposing it to a broader set of injection strings that bypass its safeguards across diverse tasks. Manually crafting such injections does not scale, so it is common practice for both industry [7], [8], [26], [27] and prior works [16], [28], [29] to pair automated red-teaming with adversarial training: Def first runs an automated red-teamer offline against πθ0 to discover injection strings satisfying Φtadv (τ ′) = 1 , and then updates θ0 on them via adversarial training to obtain πθ .RL-based red-teaming is a commonly used method for generating these training injections at scale [8], [11], [12]. Instead of optimizing a separate injection string from scratch for each task, RL trains a generative red-teaming policy 

πϕ, parameterized by ϕ, offline across a training task set. Training a shared policy πϕ amortizes exploration across tasks to produce thousands of successful injection strings at high ASR, and allows Def to initialize πϕ directly from 

πθ0 without requiring a stronger external model. Specifically, state-of-the-art RL-based red-teaming methods, RL-Hammer and PISmith, optimize πϕ with Group Relative Policy Optimization (GRPO) [30]. For each injection task tadv ,GRPO samples a group of G candidate injection strings from πϕ(· | tadv ). Placing each candidate dadv into πθ0 ’s data channel produces an attacked trajectory τ ′ and a binary attack reward

## 3. Motivating Study and Problem Analysis 

In cybersecurity, pairing offensive red-teaming with defensive blue-teaming , which here takes the form of adversarial training (§2.3), is called purple-teaming [37], [38]. This workflow implicitly assumes that a stronger red-teamer, which achieves higher ASR against the base policy 

πθ0 , uncovers more vulnerabilities, so that training on its discoveries produces a more robust policy πθ . We formalize this workflow (Figure 1) in §3.1 and examine the assumption in §3.2, along with the utility cost of adversarial training.

Remark 1: Train-Time ASR vs. Robustness 

Higher train-time ASR and larger training datasets Dtrain 

resulting from RL-based red-teaming do not guarantee stronger inference-time robustness, likely due to a lack of coverage of distinct attack strategies. 

Adversarial training can degrade benign utility. Beyond robustness, a hardened policy must also preserve benign utility (R3). Adversarial training, however, is known to induce a trade-off between robustness and utility on clean inputs [42]. This trade-off has been observed both in jailbreak defenses, where safety tuning degrades performance on benign prompts [28], [43], and in IPI defenses [21], [44].

rdef (τ ′) = 0 , just as it would for executing tadv . Although the two failures call for different corrections, this score gives the agent no direct feedback about which tokens led to either outcome [21], [22]. 

Remark 2: Utility Degradation in Adversarial Training 

On-policy RL preserves benign utility better than off-policy SFT, but supervising multi-step trajectories with a single binary outcome reward still lowers task completion rate. 

## 4. Our Method 

In §3, PISmith compromised more training tasks than RL-Hammer, yet training on its examples yielded a higher worst-case ASR in three of the four settings. If those additional successes came from reusing familiar strategies on new tasks, the collection could grow without exposing the defender to other ways of redirecting the agent (Remark 1). Since a familiar strategy can appear in an injection whose wording is new, we test this explanation by measuring how well the strategies represented in the collection explain unseen injec-tions as the collection grows (§4.1). In P IPETTE (Figure 3 and Algorithm 1), this measure also guides P IPETTE -Red (§4.2) as it collects the examples on which P IPETTE -Blue trains the defender (§4.3). 

4.1. Revisiting Red-Teaming Objectives for Defense Improvements 

From surface wording to strategy primitives. In §3.2, we hypothesized that RL-based red-teamers achieve high train-time ASR while leaving other vulnerabilities open because pairwise BLEU, sentence embeddings, and token entropy bonuses (§2.3) operate on raw injection strings dadv rather than on the attack strategies behind them. In particular, two injection strings can share almost no words yet use the same attack strategy to override tu [11], [17], because task-specific nouns such as email addresses or account numbers dominate full-string similarity. 4.3. P IPETTE -Blue: On-Policy Defensive Training 

After P IPETTE -Red produces Dtrain spanning diverse attack strategies, PIPETTE -Blue (Figure 3, right) trains the agent policy πθ on Dtrain toward the three defense requirements R1 to R3 (§2.4). 

Task-alignment reasoning and outcome-based RL. To learn generalizable defensive behavior during adversarial training, P IPETTE -Blue trains the agent policy πθ to separate untrusted data from instructions through explicit reasoning before acting. Prior work on jailbreak defense shows that training a model to reason over a fixed set of safety poli-cies before responding improves generalization to unseen attacks [49]. Following this approach, P IPETTE -Blue trains 

πθ to inspect the last observation ot−1 in its reasoning ρt

before emitting tool calls ct (§2.1). This reasoning performs two checks [4], [50]: C1 , identify whether ot−1 contains any instruction or attempt to redirect the task, and C2 , verify that every planned tool call in ct serves a goal authorized by the trusted user task tu. Under C2, observations may supply the data for that goal but cannot authorize a new one. To establish this reasoning format without distilling from a larger model, Def prompts the base policy πθ0 to generate demonstrations whose reasoning ρt follows C1 and C2. For this SFT warm-up, we use tasks in Dtasks and a weaker subset of AgentDojo’s built-in static attacks, which we exclude from evaluation. After the warm-up, P IPETTE -Blue trains πθ with on-policy RL on attacked tasks from Dtrain and clean tasks from Dtasks . Each of the G rollouts in a group receives the outcome-based defense reward rdef in Eq. 7 and a chain-of-thought (CoT) reasoning reward rCoT ∈ [0 , 1] . To compute the latter, an LLM judge checks C1 and C2 in ρt at each step and averages the binary results over the trajectory. We normalize and combine both rewards as in Eq. 12 to obtain the trajectory-level advantage Atraj .

## 5. Experiments 

To determine what the defender gains from a better training set (§3), we vary the collection and the training procedure separately (§5.2). We then evaluate the trained agent under iterative-adaptive and static attacks (R1, §5.3 and §5.4). Since a refusal can also prevent an injection, we assess utility alongside robustness (R2 and R3, §5.5) and examine how P IPETTE -Blue’s supervision affects both in an ablation (§5.6). 

5.1. Experimental Setup 

Models and benchmarks. We evaluate four open-weight models spanning three model families from 4B to 27B parameters: Qwen3-4B and Llama-8B from §3.2, GPT-OSS-20B [52], and Qwen3.6-27B [53]. Across all models, both stages of P IPETTE run offline exclusively on AgentDyn tasks [39]. At inference time, we evaluate the trained poli-cies on two unseen multi-step benchmarks: AgentDojo [2], covering the Workspace, Slack, Travel, and Banking suites, and Agent Security Bench (ASB) [54]. No user task tu or injection task tadv of AgentDojo or ASB appears in training. 

Defense baselines and evaluation protocol. In §5.2, we first evaluate the two stages of our framework individually: PIPETTE -Red (§4.2) paired with RL or SFT adversarial training (§3.1), and P IPETTE -Blue (§4.3) compared against RL and SFT on the dataset Dtrain collected by P IPETTE -Red. Continuous purple-teaming. PIPETTE currently performs a single pass of P IPETTE -Red against πθ0 followed by PIPETTE -Blue, rather than alternating between red-teaming and adversarial training across multiple rounds [20]. During PIPETTE -Red, rebuilding the rolling dictionary Dℓ every

Moreover, once πθ completes PIPETTE -Blue, even 250 -attempt online search achieves low ASR (Table 5), which may leave a red-teaming policy initialized from πθ0 with too few successful rollouts to bootstrap a second round. Nevertheless, a single pass cannot reveal vulnerabilities that emerge only in the hardened πθ,so we leave multi-round purple-teaming to future work. 

Scope of the evaluation. Our iterative-adaptive evaluation is bounded by its attack budget (two search-based attacks, around 250 attempts per task pair, a 4B attacker LLM, and 

40 task pairs), so a larger budget may achieve higher ASR. Moreover, the LLM grader behind ES has not been validated against human labels, and we do not establish low strategy coverage as the sole cause of the gap between train-time ASR and robustness. 

## 7. Conclusion 

We find that pairing high-ASR RL-based red-teaming with standard adversarial training does not necessarily make LLM agents robust to unseen attacks. The red-teamers we study exhibit strategy-level mode collapse, and adversarial training with off-policy SFT or trajectory-level outcome rewards can reduce benign utility. To address both problems, we present P IPETTE , a two-stage prompt injection purple-teaming framework. P IPETTE -Red guides RL-based red-teaming with a rolling strategy dictionary to keep uncovering new attack strategies, and P IPETTE -Blue then combines task-alignment reasoning with a contrastive token-level reward to help the agent ignore injections while completing user tasks. Across four open-weight models trained on Agent-Dyn, P IPETTE achieves lower average ASR on the unseen AgentDojo and ASB benchmarks than the training-based and non-training-based baselines while preserving benign utility. ## Appendix C. Evaluation Protocol 

Benchmarks. We train both stages of P IPETTE and the baselines in §3 on the 560 task pairs in Dtasks from AgentDyn’s Shopping, GitHub, and Daily Life suites [39]. Because AgentDyn extends AgentDojo, the two benchmarks share general-purpose tools for email, calendars, banking, and files, and some injection tasks pursue similar goals, such as transferring money to an attacker-controlled account. Despite this overlap, their suites and individual user and injection tasks are disjoint. On AgentDojo ( v1.2.2 ), the clean evaluation measures BU on the 97 user tasks, each run once without injection. To evaluate the same tasks under static attacks, we use 420 pairs, 105 sampled per suite, covering all 97 user tasks and 35 injection tasks. ASB defines an attacked case as a pair of an agent and an attack tool, so we evaluate each of its five static attacks on the benchmark’s 

400 such pairs [54]. In both benchmarks, the agent policy decodes greedily at temperature 0.

Selecting the 40 task pairs for iterative-adaptive attacks. 

Because TAP and G ENETIC each spend around 250 rollouts of the agent policy on a single task pair (Table 1), attacking all 420 task pairs could take up to 209 ,160 rollouts for every row of Table 5. We therefore concentrate this budget on task pairs known to be vulnerable, namely those that static attacks already compromise on the undefended Qwen3-4B, and select 40 of them, 10 from each AgentDojo suite. On such a task pair, the undefended agent has been shown to read the injection and execute the injection task, which makes it a natural target for a stronger attack. ASR on this subset is thus best read as a stress test on previously compromised task pairs, not as an estimate of the rate over all 420 task pairs. The subset is selected once and reused for every base policy and defense, so that all rows of Table 5 are measured on the same task pairs. Specifically, we assign a task pair to Tier 1 if at least one static attack yields Φtadv (τ ′) = 1 and Φtu (τ ′) = 1 on the same trajectory, i.e., the agent executes the injection task while still completing the user task, and to Tier 2 if some static attack yields Φtadv (τ ′) = 1 but none does so with Φtu (τ ′) = 1 . Within each suite, we sort each tier by injection task ID and then by user task ID, and select 10 task pairs from Tier 1, filling any remaining slots from Tier 2 (Table 11). This selection favors pairs on which the user task was completed under attack. UA on the selected subset is therefore not directly comparable with UA over all 420 task pairs.

Running the iterative-adaptive attacks. Both attacks follow the configurations in Table 1. The attacker LLM is huihui-ai/Huihui-Qwen3.5-4B-abliterated 

and the judge LLM is huihui-ai/Huihui-Qwen3-4B-Instruct-2507-abliterated , which are pub-licly available variants of Qwen3.5-4B and Qwen3-4B with refusal behavior removed; we choose these variants because a safety-aligned attacker LLM often declines to write injection strings. For each task pair, the attacker LLM starts from the description of tadv , and each candidate dadv is placed at the injection position that AgentDojo defines for that pair before πθ is rolled out in the contaminated environment. All tool calls and observations of each attacked trajectory are visible to the attacker. The judge LLM scores each failed candidate from them, and the attacker LLM proposes new candidates from the goal of tadv and its earlier candidates with their scores. TAP also discards candidates that drift from tadv before running them and expands only the highest-scoring ones, whereas G ENETIC mutates a parent using other evaluated candidates as inspirations. Both attacks use the prompts of their public implementations unchanged, with no instructions specific to P IPETTE . Success is decided only by the injection-task checker of AgentDojo, and the search terminates at the first candidate with Φtadv (τ ′) = 1 or once the attempt budget is exhausted. We report ASR as the fraction of the 40 task pairs on which the search succeeds, so that each successful search changes ASR by 2.5 percentage points, and UA over the same 40 task pairs, on the trajectory of the successful candidate or, if none succeeds, of the highest-scoring one.
